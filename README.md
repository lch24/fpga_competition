# FPGA 相机标定与图像校正分工

目标：摄像头图像写入 DDR → 棋盘角点检测 → 相机参数标定 → 图像校正 → 校正结果写回 DDR。

首版按同一相机、同一分辨率的 **3 张标定图、5 行 × 8 列内角点、k3 固定为 0** 实现。标定成功后重复使用相机参数，不对每帧重新标定。本文约定协作边界，具体算法参考现有 C++，不代表 RTL 已实现。

## 1. 三人分工

| 负责人                   | 负责范围                                                                                               | 对外输出                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| 苏晨：棋盘角点检测       | 从 DDR 读图，灰度化、多尺度检测、候选筛选、网格排序、亚像素定位；管理本模块中间数据                    | 每张图 40 个有序角点及成功/失败状态              |
| 刘承昊：相机参数算法     | DLT/Zhang 初值、各图 R/t 初始化、多初值与分阶段 LM、结果有效性检查                                     | 内参、畸变系数、误差与有效性；R/t 可作为诊断输出 |
| 强文韬：采集、DDR 与校正 | 摄像头接收与格式转换、DDR 读写服务和缓冲区管理、根据参数建表、邻域读取与插值、校正图写回 DDR、顶层调度 | 稳定图像帧、统一 DDR 服务、校正结果              |

## 2. 数据交接接口

### 2.1 强文韬 → 苏晨：待检测图像

| 字段                                  | 格式与含义                                                |
| ------------------------------------- | --------------------------------------------------------- |
| `job_id / frame_id`                 | 各 32 位无符号；任务编号、帧编号                          |
| `view_id`                           | 8 位无符号，标定视图 0、1、2                              |
| `src_base / src_stride_bytes`       | 各 32 位无符号；DDR 字节地址、每行字节数                  |
| `width / height`                    | 各 16 位无符号；三张标定图必须一致                        |
| `pixel_format`                      | 8 位；首版固定`0=BGR888`，内存每像素按 B、G、R 字节排列 |
| `scratch_base / scratch_size_bytes` | 各 32 位无符号；检测工作区的地址和容量                    |

坐标从 `(0,0)` 开始，x 向右、y 向下，整数坐标表示像素中心。地址公式为 `src_base + y*src_stride_bytes + 3*x + channel`。第三人负责把摄像头原始格式转换成约定格式；第一人自行灰度化。

第一人在分配的 scratch 内存放灰度、金字塔和响应图等，提交最大工作区需求；第三人负责分配互不重叠的区域。源图在检测完成前不得被覆盖，后续还要校正的帧须继续保留。

### 2.2 苏晨 → 刘承昊：有序角点

每张图成功时输出恰好 40 个点，单点数据包为：

```text
job_id[31:0], view_id[7:0], point_index[7:0], x_fp32[31:0], y_fp32[31:0]
point_index = row*8 + col，依次为 0…39
```

- x/y 为 IEEE 754 FP32，单位是像素，必须恢复到原图分辨率；不能输出缩图坐标或无序候选点。
- 图像尺寸、棋盘规格由顶层随标定命令传入；三组角点属于同一个标定任务。
- 第二人的输入缓存用 valid/ready 接收 120 个点，只有全部收齐且三次检测均成功，才接受标定启动命令。
- 检测失败时不提交有效点集；若已传出部分数据，顶层根据失败响应作废该视图，不能补零凑数。

### 2.3 刘承昊 → 强文韬：相机参数

标定命令包含 `job_id、width、height、square_size_fp64`；首版棋盘规格固定 5×8，格长未知时 square_size=1。第二人自行管理内部迭代状态。

成功时通过一笔参数包传递：

```text
calib_id[31:0]（取本次 job_id）, width[15:0], height[15:0], camera_valid
9 个 FP32：fx, fy, cx, cy, k1, k2, k3, p1, p2
```

**参数顺序固定为上述顺序**，不能直接照搬内部 LM 状态数组。k3 仍保留字段但值为 0。`camera_valid` 表示通过最终有效性检查，不等于“迭代运行结束”。RMS（FP64）、converged、weak_geometry 随诊断报告输出，weak_geometry 单独为 1 不自动否定参数。

第三人只在参数包和成功完成响应均收到后使用新参数；映射表绑定 calib_id 和图像尺寸，建表完成前不得切换。标定失败不能静默使用半成品参数；旧参数是否继续用于普通帧由顶层明确控制。

## 3. 所有模块统一的时序规则

| 接口      | 统一规则                                                                                       |
| --------- | ---------------------------------------------------------------------------------------------- |
| 命令      | `cmd_valid/cmd_ready/cmd_payload`，仅握手成功时锁存全部字段                                  |
| 数据流    | `data_valid/data_ready/data_payload/data_last`；角点 last 标记每视图第 40 点，参数包为单拍   |
| 完成响应  | `rsp_valid/rsp_ready/job_id/status`；status=0 成功，非零为错误码                             |
| 背压      | valid=1 且 ready=0 时，valid 和全部载荷保持不变；只有握手才推进数据计数                        |
| 并发      | 首版每个算法模块只接一个任务，未完成任务的响应被接收前不接新任务                               |
| 完成含义  | 输出数据已被接收，且所属 DDR 写事务达到适配层约定的完成边界后，才报告成功                      |
| 时钟/复位 | 算法和 DDR 服务统一使用 IP 输出的 core_clk；低有效复位 rst_n，同步释放；摄像头跨域由第三人处理 |

完成响应表示本次任务结束，成功由 status 判断。首版错误码统一为：`0=OK、1=BAD_CONFIG、2=NO_BOARD、3=BUFFER_OVERFLOW、4=CALIB_INVALID、5=MEM_ERROR、6=TIMEOUT`；阶段、视图和迭代号作为诊断字段，不挤进错误码。MEM_ERROR 只报告适配层实际能检测到的错误。

## 4. DDR 服务：由强文韬统一提供

第一人及其他算法模块不能直接驱动 DDR IP。算法侧一律使用 **32 位字节地址和字节长度**，地址单位转换、对齐、256 位数据拆包、仲裁和跨域由第三人处理。

为方便独立开发，首版逻辑读写数据口采用 **32 位数据宽度**；第三人在内部聚合/拆分 DDR 的 256 位数据。后续扩宽需统一修改接口定义。

| 通道   | 载荷（各通道均使用 valid/ready）                                      |
| ------ | --------------------------------------------------------------------- |
| 读请求 | `addr[31:0], len_bytes[31:0], tag[15:0]`                            |
| 读返回 | `data[31:0], keep[3:0], tag[15:0], last, error`                     |
| 写请求 | `addr[31:0], len_bytes[31:0], tag[15:0]`                            |
| 写数据 | `data[31:0], keep[3:0], last`；请求握手后发送，首版不交织多笔写数据 |
| 写完成 | `tag[15:0], error`                                                  |

- 请求长度必须大于 0。服务层支持任意合法字节起点；首个返回/写入字节放在 data[7:0]，随后按低位到高位排列，尾拍用 keep 标记有效字节。
- 每个客户端首版最多一笔读、一笔写在途；独立客户端口由服务层仲裁，tag 在该客户端内匹配请求，不假设固定返回延迟。
- 支持换地址读取，连续性只限于单笔请求；跨块、行尾有效字节和像素跨拍由服务层处理。写图不能破坏行尾 padding。
- 当前 DDR IP 没有 rready，服务层必须在发请求前预留全部返回数据所需的接收容量；算法侧可以背压，IP 返回数据不能丢。
- 当前 IP 不是完整标准 AXI，写完成判据由第三人根据该 IP 明确定义和验证；**不能把写入软件侧 FIFO 当作 DDR 已写完**。写后立即读取须保证次序和可见性。
- 摄像头不得覆盖正在检测或校正的帧。首版检测、标定、校正串行调度；持续采集只能写空闲缓冲区，无空闲区时按约定丢弃整帧，不能破坏在用帧。

## 5. 公共规范与公共模块

共用模块首先指 **共用源码和行为约定，各模块可以分别实例化**。首版不强制共用一个物理运算器；以后需要节省资源时再增加仲裁，不能隐含要求另一个人的模块让出硬件。

| 公共项                        | 共同约定                                                                | 首版维护归属                       |
| ----------------------------- | ----------------------------------------------------------------------- | ---------------------------------- |
| `rtl/common/vision_defs.vh` | 接口位宽、字段排列、格式码、错误码和能力上限的唯一来源                  | 第三人整理，三人确认               |
| FIFO、RAM、CDC 封装           | 读延迟、满空、复位、同址读写语义；跨域只用约定封装                      | 第三人                             |
| 浮点运算封装                  | FP32/FP64、valid/ready、舍入、异常、延迟和启动间隔                      | 第二人维护公共封装，使用者负责集成 |
| 双线性插值核                  | 输入 p00/p10/p01/p11、dx/dy，输出 FP32；不含访存、边界处理和 uint8 舍入 | 第一人维护，第三人复用             |
| Brown 畸变核                  | 系数顺序 k1/k2/k3/p1/p2；FP64 标定与 FP32 建表分别实例化                | 第二人维护，第三人复用             |
| C++ 参考数据                  | 同一套输入图、阶段输出及参数；记录数据版本                              | 各人导出自己负责阶段，联合保存     |

统一使用 IEEE 754 浮点位模式传输数值；角点和最终相机参数用 FP32，标定内部关键累加和矩阵运算沿用 FP64。DDR 多字节字段按小端排列。跨模块位域布局以 vision_defs.vh 为准，不直接复制带 padding 的 C++ struct。

公共 RTL 使用可综合 Verilog，测试平台可用 SystemVerilog；禁止把 real 或仿真数学函数当作可综合运算器。公共核文件头写明输入输出、数值类型、握手、延迟/启动间隔和复位行为。更换公式、数值位宽、舍入或字段顺序时同步修改参考模型与对拍用例。

以上公共文件是待建立的协作约定。最大分辨率、工作区容量和各 IP 配置在开始连接模块前共同冻结，并写入统一定义；禁止三个人分别维护不同版本。

## 6. 独立开发与联调

1. 第一人使用预存图像和仿真 DDR 服务，验证角点顺序、精度、失败处理及工作区访问。
2. 第二人使用 C++ 导出的三组角点，验证初值、LM、参数和有效性，不等待硬件检测完成。
3. 第三人使用已知相机参数或参考映射表，先跑通采集/存储及 DDR→校正→DDR，再接入前两人的结果。
4. 联调先传固定角点和固定参数包，验证接口；再用三张预存图跑完整流程，最后接实时摄像头。

每人交付：模块、接口说明、独立 testbench、参考输入输出和已知限制。共同测试随机背压、失败响应、重复任务和复位；图像类对拍必须检查 padding、像素次序和输出数量。接口变更先更新统一定义并通知使用者，再修改实现。
