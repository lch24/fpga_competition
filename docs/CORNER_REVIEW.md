# 检测角点 → 红点查看 → 再次确认计算参数

启用角点查看后，检测与参数求解之间增加人工确认阶段；查看图复用原照片的副本，求解仍使用保存的亚像素坐标。

## 用户操作

1. 沿用 KEY0、KEY1、KEY2 拍摄三张照片。
2. 第一次按 KEY3：只对三张照片依次检测、排序、细化并保存最终角点，不计算相机参数。
3. 三张全部成功、查看图制作完成后，**LED6 亮**，默认显示第一张照片的红点查看图。LED5 此时不亮。
4. KEY0、KEY1、KEY2 切换三张保存照片，每张叠加其各自的 40 个红点。查看阶段持续显示，不再两秒后返回预览，也不会重新拍摄。
5. 检查红点是否落在真实内角点、有没有跳行或混入背景。再次按 KEY3：先停止显示并排空，再用**刚才保存的同一批 FP32 亚像素坐标**计算参数，不重新检测。
6. 参数成功后 LED5 亮，返回原预览；KEY4 建表和实时视频、KEY0 视频前后切换、KEY4 停止/重启不变。

查看图加载期间 LED4 表示忙，重复按键不排队。第二次 KEY3 也需要独立的一次按下，长按同一次不会连续触发计算。查看时 KEY4 不启动建表；参数尚不存在。LED6 在后续校正成功后仍保留原来的“有校正结果”含义，因此要结合阶段解释。

显示的是**实际准备交给标定的最终有序 40 点**，不是全部 Harris/环形筛选前的候选点。检测失败仍报原错误，不亮就绪灯、不允许继续参数求解；失败候选点可视化不是本版功能。红点存在也不自动证明网格顺序正确，人工仍需结合棋盘观察。显示标记为 5×5 红色小方块，中心取最近整数像素；求解仍使用原始 FP32 坐标。

若发现角点不对，可以停在查看阶段不确认。当前有效照片槽仍不支持单槽覆盖重拍，重采一组仍需重新 program/全局复位；照片生命周期由板级流程统一管理。

## 资源与数据安全

```text
KEY3 → 三张原照片检测 → 保存 120 个最终角点 → 等待确认
                                              │
KEY0/1/2 → 原照片 → 现有 remapper 恒等复制 → 输出槽 0 → 顺序写红点 → HDMI
                                              │
再次 KEY3 ────────────────────────────────────┘→ 原坐标 → 初始化/LM/检查
```

- 原照片在 `00000000/00200000/00400000`，不在原图上画点。
- 查看副本复用实时输出槽 0 `0x01000000`，不新增整帧 BRAM、不分配新的 DDR 槽位。查看期间实时视频未启动；进入视频后输出槽按原规则完整覆盖再发布。
- 复用一个现有 `realtime_remap` 做整数坐标恒等复制，不读去畸变 map，不加第二套 cache/插值器。
- 复制完成响应包含最后一次物理写回完成；然后标记 DMA 才能接管同一个原生写客户 2。没有增加第四个 DDR 写客户，也不复用正在运行的算法写客户。
- 标记 DMA 顺序扫描坐标，逐个做带字节掩码的单 beat 写入，最多 40×25 次写/张。等待 WUSERO_LAST，不把最后 WREADY 当作完成。复制或标记失败不会启显半成品，不允许按 KEY3 继续；可选照片键重新制作查看图。
- 从算法角点握手处镜像数据，经 72 位小异步 FIFO 到核心域；FIFO 满时与原角点存储一起背压，不静默丢点。核心端只有 120×25 bit 的整数显示坐标 RAM，无整帧缓存。显示位置转换不实例化浮点运算核。
- `vision_sequence.REVIEW_WAIT=17` 保持 worker 复位释放；`calib_top` 在已有 WAIT_CMD 等待，不清角点、不启动初始化或 LM。UI 从第三张的 LEASE 进入查看，第三张原照片一直保留到求解结束。确认电平经两级同步，等 review_wait 撤销才完成确认握手，再于 RESULT 接受最终照片释放和任务响应。
- 查看当前图时先停显排空，再覆盖副本；所选照片号和标记点集一致。每次新任务的第一个角点使旧显示点集失效，完整接收 120 点后才允许查看。

新增资源主要是小坐标 RAM、异步 FIFO、像素地址/写掩码及状态机。没有 40 路逐像素并行坐标比较器，没有修改标定数值精度。**节约设计不等于资源已经通过**，仍需看新综合/布局中的 LUT、簇、RAM 与关键路径；不提供未经实测的面积保证。

## 独立 PDS

权威顶层增加 `ENABLE_CORNER_REVIEW=0`，默认保留旧单次 KEY3 行为。查看版支持普通实时配置：`REALTIME_VIDEO=1, ENABLE_DISTORT_DEMO=0, ENABLE_CORNER_REVIEW=1`。暂不与人工畸变演示扩展同时启用，不改变基础工程的其他编译参数。棋盘固定为三张、5×8 内角点；其他配置会显式拒绝展开。

在仓库根目录运行：

```powershell
python scripts/build/prepare_corner_review.py
```

然后打开 **仓库**下 `OV5640_DualView_100H/CornerReview.pds`。生成器离线派生 `build/review/project_top.v`，只替换两个参数默认值，保留原模块和 PLL/DDR 实例层级；include、源码/IP、ROM 均在仓库内。旧实现状态置 INVALID；不启动 EDA，不综合、不 program。修改顶层后需重新生成，勿手改派生顶层。生成工程和 ROM 镜像不入库，可重复生成。

## 在计算前检查 k3 覆盖

当前 `AUTO_K3=1` 是保护策略，不是 k3 算不了。初始化读取所有三张图的**实际检测角点**，要求四个边缘带各至少 4 点：

| 区域 | 1280×720 下的实际阈值 |
| --- | --- |
| 左 | x ≤ 319.75 |
| 右 | x ≥ 959.25 |
| 上 | y ≤ 179.75 |
| 下 | y ≥ 539.25 |

按三张累计，角落里的同一点可以分别计入水平、竖直两个带。纸张/屏幕外沿到了边缘不算，必须是检测出的内角点。任一带不足就在**第一次拟合前**固定 k3=0，同时仍拟合其他参数；不是算出 k3 后直接抹零。已有记录 `low_coverage=true,reduced_model=true` 属于这条路径。

进入 LED6 亮的查看阶段，可先执行只读检查，暂不按第二次 KEY3：

```powershell
python scripts/debug/probe_corner_coverage.py COM11
```

工具逐点读取板上刚找到的 120 点，检查任务号、页号和算法是否停在等待/空闲，统计每张与总体四带计数、角点范围及网格几何。它不发运行控制命令、不修改参数；在视频期间也可审计仍保留的角点。若串口无回复，先检查连接，不凭旧归档冒充本轮计数。

在计算前，板上的 low_coverage/reduced_model 还没有本轮求解结果，工具将这两项显示为 null，只给独立计数和“覆盖门槛是否允许 k3”的预测。**覆盖合格也不保证最终一定采用完整模型**：完整模型若映射翻折，仍会降阶重新拟合。求解后 `reduced_model=true,low_coverage=false` 才是翻折重试。

解决“经常启用不了 k3”优先做两件事：用红点检查定位/网格是否正确，再按计数补足缺失的边缘带并改变拍摄倾角。不要只在中央旋转，也不要为碰到边缘而裁掉棋盘或让格距过小。仓库 2026-10-22 已有真实鱼眼完整模型成功记录，证明流程能启用 k3；本次保持原判据，不把 AUTO_K3=0 或降低门槛当作正常修复。

k3 项乘的是归一化半径的六次方，中心数据对它约束弱；已有集中角点样例在低 RMS 下仍能得到很大的 k3 并使边缘翻折。因此 k3 不为零本身不是质量指标；最终应检查独立区域的直线误差与映射有效性。具体记录见 [CALIBRATION_QUALITY.md](CALIBRATION_QUALITY.md)。

也可在等待确认时导出坐标：

```powershell
python scripts/debug/uart_monitor.py COM11 --corners data/debug/review_corners.json
python scripts/debug/inspect_calibration.py data/debug/review_corners.json
```

已有 inspect 工具不传图片时只显示点阵；若要在电脑叠加原图，必须使用 DDR 中同一张保存帧的 1280×720 原始图，不能拿之后的实时帧或手机拍屏图冒充配准底图。本版的 HDMI 标记由同一保存照片副本制作，不存在这个配准歧义。

测试覆盖标记所有视图、5×5 标记及边界裁剪、写掩码、背压、延后物理完成、错误与新任务失效；两次 KEY3、三图持续查看、显示排空和失败禁确认；控制／CDC／标记与实际复制器、DDR 仲裁联动。日志写入 `build/review`。
