# 可移除的人工畸变演示

此功能用于摄像头原生畸变不明显时，验证“畸变图像 → 角点检测 → 标定 → 校正”的完整数据交接。它不是给标定算法提供答案：人工系数只用于生成输入图像，校正表只能使用标定模块实际输出的参数。

## 编译与操作

板级顶层 `rtl/top/calibrated_view_top.v` 的 `ENABLE_DISTORT_DEMO` 默认 **0**。设为 **1** 后重新生成比特流，启用演示功能；恢复 **0** 并重新生成比特流，即回到普通版本。演示扩展要求当前默认的 `REALTIME_VIDEO=1`、1280×720 配置。

关闭时，顶层直接实例化原 `video_board_flow`，不实例化演示调度器、长按计数器和双闪指示电路。建表中的逆映射分支、专用命令译码与演示调试页同样受编译参数控制。源码仍可留在工程文件列表中，不代表这些模块会占用硬件。不要通过删除共享文件来关闭功能。

启用后的操作：

1. 上电仍处于模式 0，正常拍照和标定。KEY3 改为释放时确认短按，长按两秒切换模式。
2. 切换请求会停止接收新操作，安全完成已接受的采集、计算和 DDR 事务，然后清空三张照片、标定参数和校正表的有效状态。期间黑屏，LED4 表示忙；重复切换不排队。
3. 首次进入模式 1 时，先生成固定的人工畸变表。成功后 LED0 双闪；再次切换回来可以复用该表。全局复位使其失效。
4. 人工表就绪后自动预览加畸变后的输入。按 KEY0～2 拍照：排空预览任务，摄像头新帧先写临时区，加畸变后写入照片槽，最终写回成功才点亮对应 LED、显示照片 2 秒，再回到预览。再按已成功的照片键只回看 2 秒。预览与拍照使用同一人工表，但不复用人工表作为校正表。
5. KEY3 短按：从这三张畸变照片检测角点并独立标定。KEY4：按标定结果建校正表，开始实时演示；每帧先加畸变，再校正。允许新帧率低于正常模式。

**运行时切到模式 0 不会释放硬件资源。** 换摄像头后要节省资源，必须把编译参数恢复为 0。尚未进行本次改动后的综合，关闭配置的最终面积仍需看 PDS 报告。

视频阶段短按 KEY0 切换校正前／校正后，默认显示校正后。校正前显示人工加畸变的结果：共享重映射器只执行人工表那一遍，直接写入显示输出槽；校正后执行人工表和独立标定校正表两遍。切换不重新建表、不清除标定结果，在途帧完成后逐帧生效。KEY4 仍用于停止，退出视频后 KEY0 恢复第一张照片功能。

## 硬件组织与数据流

`rtl/control/demo/distort_demo_flow.v` 包装现有板级流程，负责模式切换和图像任务调度。照片租约、标定交接、视频输入三槽和显示双槽仍由原流程管理，不维护第二份实现。

```text
拍照：摄像头 → 临时原图 → 人工畸变重映射 → 照片槽 → 显示 / 检测 / 标定
视频：摄像头 → 视频原图槽 → 人工畸变重映射 → 中间帧
                                                  ↓
                       HDMI ← 校正结果槽 ← 标定结果重映射
```

两遍处理共享同一个 `realtime_remap`，包括源像素缓存、插值器和突发写回器。调度器改变每次命令的源、目标和表地址，不复制第二套图像电路。第一遍失败不启动第二遍；第二遍失败不发布结果。模式切换不强制复位 DDR 或撤销已经提出的 VALID。

建表共享现有 `packed_map_builder` 和 FP32 服务。人工逆映射控制位在编译关闭时为常量，额外迭代分支也受编译开关保护。

新增 DDR 区域均为字节地址，只用于启用的演示版本：

| 内容 | 起始地址 | 预留大小 |
|---|---|---:|
| 拍照前的原始帧 | `0x01400000` | 2 MiB |
| 实时两遍处理的中间帧 | `0x01600000` | 2 MiB |
| 人工畸变表 | `0x03800000` | 8 MiB |

三张照片仍在 `0x00000000 / 0x00200000 / 0x00400000`，标定结果生成的校正表仍在 `0x02000000`。不会原地读写同一图像，也不会覆盖检测工作区。

## 人工畸变与独立标定

默认虚拟焦距为 `floor(0.8 × WIDTH)`，720p 下是 1024；中心为 `(639.5,359.5)`，`k1=-0.18`，其余畸变系数为零。只提供这一种固定桶形畸变。

对于人工畸变图中的目标像素，先归一化得到 `(xd,yd)`，从 `(x,y)=(xd,yd)` 开始，重复 16 次：

```text
d = 1 + k1 × (x² + y²)
x = xd / d
y = yd / d
```

最终坐标对应正常输入图像的采样位置，使用现有 64 位描述符、双线性插值和越界黑边规则。这是在反解径向模型，不能用简单改变系数符号替代。

模式命令通过已有原子 start FIFO 传输，不对多位信号直接跨时钟采样。编译开启时，`start_remap=1` 配合 DDR 范围外的两个内部值表示特殊命令：`0xffffff00` 仅生成人工表，`0xffffff04` 清空参数有效状态。定义集中在 `rtl/include/distort_demo.vh`。人工建表使用 opcode 3，普通校正建表仍使用 opcode 1。

人工建表不写 `vision_sequence.params`，不触发标定成功，也不向初值和 LM 传入人工系数。切换模式会同时清除参数调试记录的有效位。真实摄像头本身的畸变会叠加，因此独立标定得到的参数不必等于人工系数。

## 时间与串口

本实现优先复用资源。实际 FP32 仿真抽样平均每个逆映射坐标约 1753 个算法周期；按 40 MHz 折算，720p **仅坐标计算约 40.4 秒**，完整首次建表还要增加 DDR 写表时间。这是一次性准备，不是每帧开销，也不是实测上板时间。

模式 1 每帧执行两次重映射，新帧率需要上板测量，不承诺 30 fps。原模式 0 没有增加第二遍处理。

```powershell
python scripts/debug/uart_monitor.py COM5 --once status
python scripts/debug/uart_monitor.py COM5 --once demo
```

状态页增加 `distort_mode`、`mode_pending`、`demo_map_ready`。演示查询 opcode 为 `0x45`，页号 `0xfffc`，沿用原包长和 CRC。返回模式调度、拍照和重映射状态、第一/第二遍周期、两遍周期之和、失败次数及人工建表耗时毫秒数。只有开启演示功能的比特流接受该查询。

## 验证与复现

```powershell
python scripts/demo/run_checks.py --modelsim <ModelSim目录> --board
scripts\demo\run_images.cmd
```

前者自动生成独立双精度坐标参考，再运行定向 RTL 测试；`--board` 额外编译整板并分别展开关闭、开启两种配置，厂商 IP 使用端口桩，不运行综合。后者使用已有 C++ 检测和标定代码，依赖 Visual Studio 与 OpenCV，可通过 `VS_ROOT`、`OPENCV_ROOT` 指定工具位置。生成图片、数值和日志全部在 `build/demo`。

本次结果：

| 验证 | 结果 |
|---|---|
| 长短按、模式切换、拍照错误重试、命令背压、两遍调度、切换排空和缓存表复用 | RTL 通过 |
| 人工建表不得产生标定结果、切换清空参数、普通建表保持原参数来源 | RTL 通过 |
| FP32 逆映射坐标 | 2,131 个位置通过，误差小于 0.05 像素 |
| 全幅软件逆映射与独立双精度反解 | 最大坐标误差约 0.000137 像素 |
| 三张真实照片先加畸变，再运行生产 C++ 检测与标定 | 每张 40 个点，RMS 0.483638 像素 |
| 三张已知三维几何的棋盘渲染图，同样从像素重新检测与标定 | 每张 40 个点，RMS 0.085669 像素 |
| 已知几何测试的校正直线误差 | 1.45766 → 0.011417 像素，降至约 0.78% |
| 默认按键、普通视频调度、普通映射建表、仅建表流程及 UART | 回归通过 |

图像闭环使用生产 C++ 检测/标定，**没有用人工系数代替拟合结果，也没有把变换后的理想角点直接喂给标定**。它不是全链路 RTL 数值仿真；RTL 验证覆盖此次新增的坐标计算、建表、调度和参数隔离。FPGA 上的最终画质、帧率、资源和时序仍需重新生成比特流验证。
