# 实时视频链路

## 数据流与时钟

标定和建表在 40 MHz 算法域运行；视频校正、DDR 仲裁与帧调度在 125 MHz 域运行。相机像素流与 HDMI 显示通过跨时钟 FIFO 连接。参数不变时复用映射表，持续视频无需逐帧执行浮点标定。

```text
相机 → 三槽原图 DDR → 源像素缓存 → 定点插值 → 双槽结果 DDR → HDMI
                                  ↑
相机参数 → 一次建表 → 稀疏网格读取与坐标插值
```

板级实时实例采用 `GRID_MAP=1, MAP_STEP=4, CACHE_INDEX_BITS=7`。地图保存每隔 4 像素的源坐标控制点，由三行缓冲和定点插值恢复逐像素坐标。原生 HMIC 地址为 **32 位字地址（字节地址 / 4）**，算法侧逻辑接口使用字节地址。

## 操作与阶段

1. 摄像头就绪后自动预览。KEY0～KEY2 拍摄空槽位；拍照成功或查看已有照片时显示 2 秒，然后回到预览。
2. KEY3 启动检测与标定；启用[角点查看](CORNER_REVIEW.md)时，检测后先查看红点，再按 KEY3 确认求解。
3. 参数成功后，KEY4 排空当前视频事务并建表。建表成功后自动进入校正视频，默认显示校正后。
4. 视频中 KEY0 切换校正前／后；模式随新任务锁存，已提交的任务保持不变。KEY4 停止新任务，排空在途采集、校正与显示，返回预览。
5. 再次进入视频可复用地图；重新标定会使旧地图失效，全局复位清除照片与参数有效位。

预览复用相同帧槽与重映射器，普通输入采用恒等采样，不需要标定参数。人工畸变模式的预览和拍照先执行人工映射，校正表仍独立从检测角点求得的参数建立。仿射与 Gamma 的调度见[增强功能](ADVANCED_DYNAMIC_GAMMA.md)。

## 模块与交接

| 模块 | 职责 |
|---|---|
| `control/system/video_board_flow.v` | UI、照片占用、地图有效位、原图和结果槽所有权 |
| `video/dma/video_capture_hmic.v` | 相机描述符排队、START/DATA/END 跨域、帧写入与完成响应 |
| `common/async_bram_fifo.v` | 双时钟块 RAM 队列，输出保持与跨域背压 |
| `compute/geometry/packed_map_builder.v` | 复用坐标计算服务，建立网格或逐像素映射表 |
| `image/remap/realtime_remap.v` | 锁存帧任务，调度地图、缓存、插值和写回 |
| `image/remap/video_grid_prefetch.v` | 网格预取、三行轮转缓冲和逐像素坐标插值 |
| `image/remap/video_map_prefetch.v` | 非网格配置的打包地图预取 |
| `image/remap/video_neighbor_cache.v` | 奇偶行分银行、块填充、tag 查找与帧间失效 |
| `image/kernels/video_bilinear_pipe.v` | 弹性定点流水，RGB565 双线性插值与一次舍入 |
| `video/dma/video_frame_writer.v` | 双块写缓冲、突发请求与物理写完成确认 |
| `memory/ddr/video_hmic_arbiter.v` | 读写独立仲裁，显示优先及其他客户轮转 |
| `video/dma/board_display_hmic.v` | 帧边界锁存基址，向 HDMI 队列发送完整帧像素 |

所有 ready/valid 命令仅在 `valid && ready` 时交接，背压期间保持载荷。HMIC 没有 RREADY 和 WVALID：读客户必须容纳整个已接受突发，写客户在请求前准备整段数据。各方向只允许一笔在途事务，收到 RLAST／WUSERO_LAST 才能切换客户。

相机前端在 HREF 行内配对 RGB565 字节；行尾不足时补齐、超长时丢弃多余字节。帧级写入限制总像素数，并将短行、尺寸、FIFO 和写回异常编码进完成响应，避免损坏帧被当成正常帧发布。

## 帧所有权与异常

- 原图槽：空闲 → 预留采集 → 完整帧就绪 → 校正持有 → 空闲。就绪队列按完成顺序处理。
- 结果槽：空闲 → 校正／写回 → 就绪 → 显示持有 → 空闲。最后一次物理写完成后才发布新结果。
- 显示读取器在整帧边界锁存新基址，随后释放旧槽。没有新结果时重复旧完整帧，不增加新显示帧计数。
- 无可用原图槽时跳过整帧，不覆盖被占用的地址。停止时已接受的事务必须完成，不能直接释放在途槽。
- 短帧、溢出、返回 ID／LAST 异常及写错误使当前帧失败；失败结果不送显示。HDMI 欠载时丢弃余帧，等待新的完整帧边界恢复。

相机停钟或 DDR 不再返回完成时，排空过程可能持续等待。应先读取诊断并联合复位相关链路，不能只复位仲裁器后立即复用在途地址。

## DDR 布局与映射格式

| 内容 | 字节基址 |
|---|---|
| 标定照片 0／1／2 | `00000000`／`00200000`／`00400000` |
| 视频原图 0／1／2 | `00800000`／`00A00000`／`00C00000` |
| 视频结果 0／1 | `01000000`／`01200000` |
| 映射表 | `02000000` |
| 灰度金字塔 | `03000000` |
| 候选区 | `03200000` |

每份 RGB565 图有效数据 1,843,200 字节，帧槽预留 2 MiB。完整图像与地图位于 DDR，片上保存窗口、缓存、FIFO 和计算工作区。

网格模式的 64 位控制点保存两轴定点坐标；运行时插值后产生 floor 坐标、Q0.16 小数和邻域有效掩码。兼容的逐像素表使用 `[15:0]=dx`、`[31:16]=dy`、`[45:32]=x0`、`[59:46]=y0`、`[63:60]=mask`，x0/y0 为有符号 14 位。越界邻域补黑，负坐标按符号解释。

缓存按 128 B 边界填充，帧间清除有效位，防止循环复用基址后命中旧像素。普通命中、跨 beat 和缺失的延迟不同；较大旋转或不连续采样会降低局部性，因此吞吐应结合实际映射测量。

## 验证与测量

```powershell
python scripts/build/check_rtl_layout.py
powershell -ExecutionPolicy Bypass -File scripts/system/run_realtime_checks.ps1 -ModelSimBin <ModelSim目录>
python scripts/debug/uart_monitor.py --self-test
python scripts/debug/uart_monitor.py COM7 --once video
python scripts/debug/uart_monitor.py COM7 --video-seconds 10
```

测试覆盖坐标打包、网格插值、连续采集、帧所有权、停止重启、边界采样、缓存失效、原生仲裁背压与错误排空；板上状态通过 UART 的视频页读取。该页保存采集、校正、新显示、失败、跳帧计数及最近校正周期，按查询窗口的增量评估吞吐。

125 MHz 下，30 帧／秒对应每帧约 4,166,667 周期。单帧重映射周期、持续新帧率和相机到屏幕的端到端延迟应分别记录；开启两遍仿射或人工畸变时，还要记录两遍各自周期。正式性能结果见[设计文档](../report/设计文档.md)，每份比特流的资源与时序以其对应 PDS 报告为准。
