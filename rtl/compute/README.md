# 计算数据通路与共享服务

`service` 负责共享执行器、请求仲裁、响应归属；`float` 负责算术和复杂函数；`geometry` 负责旋转、投影和整批残差。

标定执行器、残差及检测精修接入共享 FP64 池。检测另有四客户端的 FP32 成对加减池和距离池。`feature_program` 计算张量位移、更新和收敛量，`fp_math_program` 计算数学函数内部步骤。

检测网格检查的 FP32 运算入口是 `float/fp_operator.v`。其中的 `fp32_basic_alu` 按“接收 → 解码及操作数排序 → 对齐 → 加减或乘法 → 规格化 → 舍入”执行；阶段之间有寄存器，不再把完整浮点计算塞进一个周期。加减使用 28 位中间数据（24 位有效数、3 位舍入信息、1 位进位），排序后共用一个对齐路径和一个加减器。规格化每拍移一位，保留非规格化数和最近偶数舍入，调用者按 `valid/ready` 等待完成。

`float/calib_alu.v` 是共享池的 FP64 标量运算单元。加减先按绝对值排序，再使用一个 57 位对阶路径和一个加减器；对阶的每级移位同时累计舍入信息。乘法、格式转换仍使用各自所需的数据路径，运算精度不变。

`float/fp_divsqrt.v` 是 FP32/FP64 参数化的逐拍除法、开方核。同一个实例一次只执行一项运算，除法与开方因此共用一个带借位输出的减法器，不改变迭代轮数。最终结果直接在 28/57 位尾数寄存器内规格化，再用独立一拍完成最近偶数舍入，不调用通用 256 位打包函数。普通结果收尾需要 2～3 拍；非规格化结果逐拍右移，极小结果提前归零并保留异常标志。所有阶段支持时钟使能暂停，响应背压时保持结果。

`tb/compute/tb_fp32_basic_pipeline.sv` 覆盖 FP32 基础运算的差分数值检查、背压和复位；`scripts/compute/run_calib_alu.ps1` 验证共享 FP64 单元，`scripts/compute/run_fp_operator.ps1` 验证浮点调用链及除法/开方核的暂停、背压、复位和迭代周期。网格检查测试覆盖检测端的上层调用。

`geometry_engine` 使用固定运算序列和工作 RAM，投影包装交入参数后等待结果。旧的独立高斯/Jacobi 数据通路已被标定程序替代，矩阵算法维护在 `scripts/calibration/engine`。

整体流程见[系统架构](../../docs/SYSTEM_ARCHITECTURE.md)，其他模块入口见[RTL 导航](../README.md)。
