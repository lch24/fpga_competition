# 摄像头与显示通路

`board` 管理摄像头/HDMI 配置、I²C 和显示时序；`dma` 搬运采集帧与显示帧；`stream` 处理像素格式和跨时钟流接口。

采集先裁剪，再把 RGB565 图写入命令指定的 DDR 槽位，整帧完成后才提交。显示读取选定的原图或校正图区，最后放大至 HDMI 尺寸；切换时先排空 DDR 读事务，再清空 HDMI FIFO，从新帧首恢复输出。标定、建表期间黑屏；实时预览和校正时并发仲裁 DDR。操作流程见[板上操作](../../docs/BOARD_OPERATION.md)。

## 像素流与尺寸

```text
1280×720 DVP 字节
  → camera_byte_unpack：按 HREF 计行，保留 x=160..1119、y=90..629
  → video_capture_hmic：960×540 RGB565 写 DDR
  → 检测、标定、映射、校正：全部使用 960×540
  → board_display_hmic：读取 960×540，地址按突发递增
  → video_scale_4_3：双线性放大到 1280×720
  → hdmi_pixel_bridge：跨到显示时钟域 → HDMI
```

裁剪发生在采集字节解包器内，无需先保存全图或额外读 DDR。行索引来自原始 HREF，不依赖上一行收到多少像素。短行诊断统计传感器完整 720 行，输出像素计数只统计保留区域。

`stream/video_scale_4_3.v` 是显示专用的固定 4/3 放大器。只保存两行 RGB565（960×2×2 = 3,840 字节），按行、列奇偶分为四个同步 BRAM 银行。依次填行、输出可生成的目标行，再复用已不需要的行缓存；末行末列复制边界像素。输入和输出都支持 valid/ready 背压。

放大器分为同步读 RAM、邻域选择、水平插值、垂直插值、RGB565 输出五级流水。权重只有 0、1/4、1/2、3/4，使用定宽移位和加法，无运行时除法或通用乘法器。地址和坐标用递增计数器，图像数据计算不串入 ready 路径。模块要求宽为 6 的倍数、高为 3 的倍数且不少于两行；板级尺寸满足这些条件。

`hdmi_pixel_bridge` 通过 `common/async_bram_fifo.v` 将放大后的像素跨到显示时钟域。板级队列为 2048×18 位（RGB565 与帧首尾标记），采用同步读 BRAM；消费当前像素的同时预取下一像素，连续有效区不插入空拍。输出被阻塞时保持数据，判满结果先寄存再控制写入，避免大范围 LUT RAM 写使能与指针比较串在一起。

## 时序与调试入口

采集端将 FIFO 返回 token 的锁存与解析分开，避免 BRAM 输出同拍驱动大范围控制；显示 DDR 地址先寄存，再发请求，动态帧基址模式不再在请求线上计算行号乘步长。校正插值器也在输入加寄存级，隔开源缓存选择和乘加。实际余量仍以重新布局后的报告为准。

异步 FIFO 的存储写进程与指针复位分开，避免复位组合逻辑驱动整片 RAM 写使能。
复位使指针归零，复位期间存储内容不成为有效数据；恢复后由新数据覆盖。

采集的 VSYNC/HREF/data 同级寄存后配对字节，每行重新建立字节相位。只输出实际收到的像素，不补造缺失像素。保留区域缺像素、保留行字节数为奇数或超长、原始帧行数不对，都使本帧无效；裁剪范围外的偶数字节短尾不影响保留区域。帧尾携带像素数、短行统计和四位源错误，经现有跨域 FIFO 与图像一起传递。DDR 写入会排空，但只有成功帧才更新显示/照片描述符，失败后可接收下一帧。

摄像头每次启动都执行完整序列：硬件复位 → 复位释放后等待 → SCCB 配置 → 开启视频 → 释放采集流水线。在当前 27 MHz 板级时钟下，`board_power_on_delay` 在 RESETB 拉高后等待约 38.8 ms，`reg_config` 同步接收 `initial_en` 后才允许发起写操作；分频时钟停止时，复位也能立即释放 SCCB 总线。

配置逐个检查设备地址、寄存器高低地址和数据的 ACK，失败重试当前寄存器。传感器在配置 PLL、分辨率和 DVP 极性期间保持软件待机，最后写 `0x3008=0x02` 才开启视频，收到 ACK 后置配置完成。顶层用所选摄像头的配置完成信号释放采集流水线，避免接收配置中途的尺寸或时钟变化。带电重新下载 FPGA 也走同样的启动过程。

写入 `0x4740=0x20` 保持原板级配置使用的复位极性，不额外翻转 HREF。FPGA 在 PCLK 上升沿采集，HREF 高时接收字节；寄存器位的文字描述不能替代实际模块的波形核对。FDC 对输入采用相反边沿发射的时序关系，输入延时数值仍需根据板上测量核实。

UART 的 `--once geometry` 报告传感器尺寸、裁剪原点、处理尺寸、显示尺寸、显示放大阶段和帧计数。`--once capture` 报告采集像素数、短行、队列/帧完整性信息。接口及解释见板上操作文档。

实际连接入口是 `rtl/top/calibrated_view_top.v`，时钟/引脚约束在 PDS 工程同名 FDC。厂商 PLL、DDR IP 保留在工程 `ipcore`，应用 RTL 在这里维护。

整体流程见[系统架构](../../docs/SYSTEM_ARCHITECTURE.md)，其他模块入口见[RTL 导航](../README.md)。
